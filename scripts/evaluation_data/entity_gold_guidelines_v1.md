# 实体标注规则（简版）

范围：20个不同视频的完整字幕片段，中文、英文各10段。正文必须涉及具体无人机型号，内容围绕无人机的规格、使用、维修、配件或配套软件。按实际字幕语言分类，不按标题语言分类。

当前20段、106个实体记录已由用户确认完成人工复核。后续修订仍须先读完整原文检查漏标，再核对已有条目；不参考待测模型输出改答案，不核实视频说法的现实真伪。

- 实体只保留`name`（规范名称）、`type`（类型）、`mentions`（原文中实际出现的叫法）。`mentions`去重即可，不记录字符偏移或每次重复位置。
- `text`按原始换行拆成字符串数组，每项一行，空行也保留；读取时以换行连接还原原文，不增删或改写字幕。
- 明确型号分别列出，不把Mini 4K改成Mini 4 Pro，不把Neo系列与某一代Neo混为一体。标题可辅助补明确品牌，不能补正文未提及的设备。
- 同一实体的多种叫法放在一项。同名但属于不同型号的部件，在名称中写明所属型号；新旧更换件可以分别列出。
- 类型常用值：`product`产品/设备、`component`硬件部件、`software`软件、`technology`技术/功能、`method`技术方法/操作、`fault`故障。其余有`organization`组织、`person`人物、`protocol`协议、`data`数据、`document`资料、`product_family`系列、`country`国家、`region`地区、`event`活动。无需凑齐所有类型。
- 按用户确认的口径：固件是software，完整遥控器和飞行眼镜是product；没有具体型号不改变完整设备的类型。
- 本轮是面向入图目标的实体标准，不要求保留所有语言学上的实体提及；泛泛风险、无信息量或冗余对象可由人工排除。`entities`是唯一答案，不能依据models或notes自动补回已删除实体。
- 数值、尺寸、价格、像素、帧率、时间和普通界面项不独立建实体。本轮不评属性，也不评逐字符提及识别。
- 命名飞行动作、明确维修流程或技术工艺可以标方法；不把每条普通动作指令另建实体。飞行模式、感知能力等标技术/功能。
- 条件、否定或预测中的对象仍可以被提及，但标出实体不表示相应关系成立。未发布型号、简称和转写疑点在`notes`里明确说明，人工复核后决定修订。

人工修改JSON里的实体和说明后，运行校验并重新生成阅读版即可。本轮没有开发/保留集划分、逐条复核元数据、来源哈希、JSON Schema或额外候选池文件。

## 统一判定顺序

每个候选依次回答下面三个问题，避免把名称统一或入图筛选混成实体识别：

1. **提到了什么？** 取正文中最短但完整的核心名称。传感器、镜头和传感器尺寸不是同一层级；尺寸、像素、焦距、帧率、价格和量词放属性，不混入核心名称。英文修饰词不能用来臆造型号。
2. **是哪一个对象？** 明确型号保留代际和后缀；系列与具体产品分开。相同设备的别名合并；不同设备同名部件分开，规范名写明所有者。并列比较中省略的部件名可以在规范名中补全，原文叫法保持原样。无法确定所有者时保持局部泛称，不凭邻近距离硬绑定。
3. **是否值得入图？** 当前片段在介绍、比较、维修其功能、状态或组成时可保留；只作比喻、背景、操作参照、报道来源或顺带提及的对象不自动保留。不能仅凭“有名字”决定保留，也不能仅凭“是泛称”决定删除。

边界口径：

| 类别 | 保留范围 | 排除或另存范围 |
|---|---|---|
| product | 整机、完整遥控器、完整飞行眼镜及明确型号 | 产品系列、设备内部按钮；笼统套装不因提价而另建产品 |
| component | 硬件部件及具体设备内部系统；按所有者区分 | 单独的数值参数、虚拟界面控件；不为每颗螺丝造实例 |
| software | 软件、应用、固件 | 软件页面、普通菜单项、命名飞行模式 |
| technology | 具名技术、协议之外的技术概念、实质介绍的能力/模式 | 裸分辨率、帧率、速度等参数；普通效果描述不自动建技术 |
| method | 具名动作、维修流程或工艺 | 每一句转向、点按、拆装指令 |
| fault | 有实质说明的具体故障或异常状态，不要求设备报警 | 随口说的风险、夸张表达、背景事故 |
| protocol | 明确通信协议 | 接口硬件、单独频段或频率数值 |

固件=software、完整遥控器/飞行眼镜=product为用户已确认口径。词表只辅助原文识别与规范命名，不表示产品已发布、参数正确或关系成立；不在词表中的新型号仍可抽取。

当前人工答案还包含对具体片段入图价值的选择，通用规则未必能完全推导每项人工取舍。保持106条答案不动；若发现规则与既有答案的边界分歧，在错误报告标记，不根据待测输出改答案。

## 错误分析口径

评测继续使用原有严格一对一计分。错误分析另外区分：漏识别、类型错误、部件归属错误、边界/命名差异、价值筛选、待判读。类型或归属错误可能同时计一个FP和一个FN；分类错误项数不是另一种F1。

- 漏识别：应有实体没有被提出，且没有可解释为同一实体的边界或别名输出。
- 类型错误：同一对象/原文提及被赋予错误类别。
- 归属错误：实体识别了，但明确绑定到了另一设备，或把不同设备的部件合并。
- 边界/命名差异：识别了相应对象，但名称包含属性、过长修饰或不同粒度，未匹配固定答案。
- 价值筛选：保留了原文明示但人工排除的对象，或审核删掉了人工认为应保留的候选。
- 待判读：证据不足以确定上述原因，保留原文与候选审核依据；不强行计作幻觉。

分类只用于诊断，不放宽匹配、不给名称相近的预测补分。只有读完整原文并核对候选及审核记录后，才把待判读项改成具体类别。
