# 项目进展周报（2026-10-24—2026-10-30）

根据本周提交、工作区最新改动及已有实施记录整理，重点说明实现方法与功能。

1. **无人机文档解析与多品牌资料整理**\
   使用 **PyMuPDF** 提取 PDF 正文、表格、图示和页码，扫描页通过 **Tesseract OCR** 识别，再用视觉语言模型生成图示说明。接入 DJI、Parrot 的 PDF 和 HTML 资料，将切片通过 **BGE-M3** 向量化，保存到独立 PostgreSQL 文档库和 Qdrant 集合，支持按型号检索并定位原文。无人机信息页增加 DJI / Parrot 品牌切换，展示对应型号、参数、版本和官方来源。

2. **文档批量处理与断点恢复**\
   使用 **文件哈希去重、多进程和分阶段队列**，串联文档解析、图片说明、入库和向量化，共用文档只处理一次。通过检查点和模型响应缓存支持中断续跑；加入跨进程请求预算及 HTTP 429 退避重试，处理模型限流，并生成批次进度与预览页面。

3. **文档管理与数据库浏览**\
   使用 **React + FastAPI** 新增文档管理界面，可按型号、厂商和标题查找资料，查看处理版本、正文、表格、原图、图片说明及检索切片。数据库浏览增加业务库、文献库和文档库切换，通过固定白名单与只读事务查询数据。

4. **二维 / 三维知识图谱交互**\
   使用 **AntV G6 及其 3D 扩展**，实现二维与三维切换、节点拖拽、邻居展开、悬停高亮和字幕证据查看。通过连通分量与 **k-core** 算法优先展示关联密集的区域；采用四元数控制三维旋转，支持围绕选中节点连续旋转、平移和缩放。

5. **问答证据重排与效果对比**\
   在关键词和向量混合召回之后，接入 SiliconFlow **`BAAI/bge-reranker-v2-m3`**，对 20 条候选重新排序，最多选取 8 条证据生成答案；重排失败时沿用原排序。编写 Python 评测脚本，对比不同证据数量和重排配置，记录要点覆盖、引用支持情况与耗时，用于选择配置。

6. **对话意图识别与上下文处理**\
   使用 **规则匹配、历史筛选和追问改写** 区分寒暄与专业问题：普通问候跳过检索和重排，专业追问承接有效话题，明确换话题时排除旧上下文影响。增加生成后的 **`[n]` 引用编号检查**，记录编号是否越界、是否缺少引用等诊断信息。

7. **多品牌供应链采集与定时运行**\
   通过 **品牌配置、Brave / 百度搜索、PyMuPDF 和大模型抽取**，将供应商流程扩展到 DJI、Parrot、Skydio，支持 PDF、网页和表格来源。关系、缓存和验证记录按品牌隔离，页面支持品牌筛选；使用 **systemd 用户定时器和品牌互斥锁**，让 Parrot、Skydio 的抽取与验证任务每半小时错峰执行。

8. **供应商多来源证据校验与失败重试**\
   采用 **结构化 JSON + 来源正文匹配**，将每段引用分别关联到对应 URL，校验引用、机型和年份，区分直接供货、器件采用与 OEM 代工。兼容旧 Markdown 输出，保留模型原始响应和失败诊断；增加按供应商定向重试，已用于重新处理失败记录并追加验证审计。

9. **文献数据库独立拆分**\
   使用 **PostgreSQL 一致性快照、SHA-256 校验和 Alembic 独立迁移**，将六张文献表迁入 `literature_research` 数据库。文献 API 和 worker 改用独立连接池，保留原有任务、论文、PDF 和证据数据，实现文献数据与业务主库分开管理。

10. **文本模型配置统一**\
    使用 **Pydantic Settings** 统一读取根目录 `.env` 中的 `BASE_URL`、`LLM_API_KEY` 和 `LLM_MODEL`。问答、查询优化、图谱抽取、文献分析及供应商工具共用文本模型配置，减少各模块分别维护配置的工作。
