# 实体关系抽取与审核规则

本文合并实体口径、名称归一、关系语义、版本和请求恢复说明，按 2026-11-10 代码整理。
构建操作见 [统一入口](knowledge-graph.md)，金标准与评分见 [评测说明](knowledge-graph-evaluation.md)。
逐轮模型方案和分数放在 [历史记录](knowledge-graph-history.md)，不作为当前运行配置。

## 阶段与来源

1. 从 PostgreSQL 读取视频及当前切片，优先使用字幕；无字幕时摘要只产生实体提及。
2. 每个视频判断一次主题相关性；每个切片先抽取实体与属性，保留原文提及。
3. 独立审核实体的边界、类型、身份、归属、属性及检索价值；身份明确后再去重。
4. 确定性归一实体，按兼容类型和原文位置生成有界实体对，再分类关系。
5. 小批次独立审核关系的谓词、方向、否定和条件，之后执行程序来源及语义校验。
6. 保存切片结果、拒绝原因和审核凭据，交给任务层发布与回读验证。

默认每 16 个候选实体对分类一次、每 8 条关系独立审核一次，每段最多 96 对、80 条关系。
少于两个有效实体时跳过关系；摘要不进入关系分类。实体答案、关系答案及评测 notes 不进入模型输入。

## 实体边界与价值

口径按“原文提到什么 → 对应哪个对象 → 是否值得入图”判断。
具体标注边界以 [实体规则](../scripts/evaluation_data/entity_gold_guidelines_v3.md) 为准。

- 完整遥控器和飞行眼镜为 `product`，固件为 `software`；其电路板、屏幕、芯片不能仅因名称含这些词而改类。
- 型号、具名软件、技术、明确故障和有实际操作信息的对象可保留；普通动作不逐句拆成方法，泛泛设置不冒充软件。
- IP、金额、数值、单位、配置文件名不单独作为硬件或软件实体。
- 审核可将边界收窄为原候选内部的连续原文；不能移到正文中另一对象、补造型号或缩成纯参数。
- 属性保存于本次提及，不用某个视频的一次配置覆盖同型号全部设备；属性不合格不会连带删除有效实体和关系。

人工实际取舍单独保留于 [24 项确认记录](entity-value-selection-review.md)。
标准答案有修订时，后续评测使用明确的数据指纹，不用历史 notes 覆盖用户确认的答案。

## 身份、别名与确定性归一

`surface_text` 保留原始提及；`canonical_name`、`identity_scope`、`identity_quote`、`identity_source`
保存规范身份及依据。v2 UUID 按命名空间、类型、规范名称和作用域生成。

- 明确具名实体可跨视频共享。无法消歧的 `drone`、`camera`、`it` 等泛称和具体设备部件保留视频作用域。
- 有原文回指依据时，泛称可以指向具名设备；泛称别名仍只在该视频内有效，不能触发跨视频扩展。
- 短型号不得仅凭术语表或同视频其他位置出现品牌而补全制造商。代际及 Pro/S/4K 等后缀必须保留。
- 参数与名称可以在可完整解释时分离，例如传感器尺寸或 HDR 视频的分辨率、帧率；属性仍保留逐字来源。
- 不从 Mini 4K、Cortex M7 等具名型号中拆走数字，不把不同配置合成一个属性值，也不覆盖已审核的冲突属性。
- 同一对象的多个叫法可以归一，但明确不同设备、所有者或版本仍须区分。同名部件不能在所有者不明时强行绑定。
- 归一在关系生成之前执行，入口和出口均重验凭据；不接受已有关系的输入，避免修改端点身份后留下悬空关系。

实现：[身份](../backend/app/services/video_graph/identity.py)、[归一](../backend/app/services/video_graph/normalization.py)。

## 领域词表

[术语表](../backend/app/services/video_graph/terms.json) 与 [匹配实现](../backend/app/services/video_graph/terms.py)
只为当前正文匹配到的术语提供拼写、类型及候选参考，不是产品参数或关系事实库。
只补充有正文依据的候选，仍须独立审核；不在词表中的新词也可以被识别。
型号匹配避免从未知型号截取旧型号，不能仅凭词表补造品牌。

词表、提示词和归一规则进入策略指纹。当前 golden 是开发集且出现过相关术语，
不能把开发分数解释成未见术语或新视频的泛化成绩。

## 关系谓词与方向

完整类型和谓词定义以 [Schema](../backend/app/schemas/video_graph.py) 与
[语义规则](../backend/app/services/video_graph/semantics.py) 为准。常见边界如下：

| 来源表达 | 规范方向与谓词 | 不能自动推导 |
| --- | --- | --- |
| 整体自身部件 | 整体 → `contains` → 部件 | 包装随附、保护或仅共现不能当成内部组成 |
| 包装配件/资料 | 产品 → `packaged_with` → 对象 | 不等于物理内置 |
| 品牌归属 | 产品/系列 → `offered_by` → 组织 | 规范名自行补出的品牌不构成新事实 |
| 制造/开发 | 对象 → `manufactured_by` / `developed_by` → 组织/个人 | 推出、销售不自动等于研发 |
| 产品系列 | 系列 → `has_model` → 型号 | 比较、替代不证明系列归属 |
| 内置固件、技术或数据 | 设备 → `uses` → 资源 | 不把所有 uses 都反转为外部应用 |
| 外部软件或方法工作流 | 软件/方法 → `applied_to` → 设备 | 必须有逐字工作流依据，不因共现建边 |
| 安装 | 部件/产品 → `installed_on` → 载体 | 安装与内部组成不自动等价 |
| 控制 | 控制主体 → `controls` → 对象 | 先后步骤不能冒充控制 |
| 兼容、连接 | `compatible_with`、`connected_to` | 模拟/类比不证明兼容，软件连接不冒充硬件连接 |
| 支持能力 | 设备/软件 → `supports` → 软件/协议/技术/方法 | 参数或控制变量不自动变成具名技术 |

审核可在端点不变且来源支持时修正谓词及方向。分类后、审核后执行同一规范化口径，
保留引文、断言、限定条件和端点身份；角色问题本身不是事实，分类为无关系时不建边。

`equipped_with` 仅用于原文明示的军事单位/编队装备列举，不在模型候选语言中。
它不证明常设编制或采购情况，不用于普通公司产品目录。

## 原文、断言和限定条件

关系保留 `asserted`、`uncertain`、`negated`，以及 `modality` 和条件/计划/假设/设计目标的来源范围。
来源明确肯定不代表现实事实已核实；限定条件必须随证据进入查询及问答。

- 原文先进行受限空白和排版字符匹配，简繁体回退使用固定版本 OpenCC，并要求位置可映射、唯一定位。
- 不通过翻译、同义词、删词或跨型号拼接修复引文；成功时恢复源文字符和偏移。
- 审核可使用连续原文行号修正抄写不准的引文，仍检查行号、顺序、长度及原来源/语义约束。
- 引文可定位与语义成立分别校验；真实出现的句子也可能被错误解释为组成、兼容或应用关系。
- 审核项遗漏、重复或无效不能视为通过；有界修正后仍不合格的项隔离，保留其他合法决定。

实现：[独立审核](../backend/app/services/video_graph/review.py)、
[原文及最终校验](../backend/app/services/video_graph/validation.py)、
[语义落地](../backend/app/services/video_graph/grounding.py)。

## 版本与审核凭据

版本形式为 `video-graph-v2:<model>:<policy-hash>-<extraction-effort>-<review-effort>`。
规则指纹覆盖提示词、请求、身份、结构和语义约束。模型、规则或服务改变后必须使用相应新版本，
不能把旧缓存的成功状态直接当作新规则验收。

审核凭据绑定结果哈希、规则、视频身份、标题、当前切片正文/类型/时间及邻近上下文。
保存、恢复和发布均重验。它是内部一致性凭据，不是模型语义正确的证明或密码学签名。
只改标题或邻近上下文也会影响复用，不能只检查当前切片文字。

## 重试、请求检查点与 token 统计

网络、429/5xx 和 JSON 解析故障最多重试一次；认证错误不重试。结构/覆盖不完整最多有界修正一次，
不能用重试翻转已经合法的语义拒绝。每次真实请求前续租；请求超时默认 120 秒，任务租约 300 秒。

成功且可解析的阶段响应保存于 Neo4j 本构建的 `output_json.request_checkpoints`。
复用键绑定任务、切片范围、版本、完整消息、模型参数和提供方/账户哈希，不跨任务共享原始响应。
损坏项重新请求；结构或来源失败清理对应片段的检查点；完整切片通过后只保留正常结果和审核凭据。
复用仍会执行实体归一、关系审核、原文和入库校验。

`token_usage` 按阶段记录 HTTP 尝试、真实输入/输出/缓存/推理 tokens、缺失 usage 和检查点复用；
`cumulative_token_usage` 累计同一清单已保存的用量。未知 usage 不按 0 算，本地复用不冒充服务商缓存命中。
统计不等于费用账单，也不保证捕获进程突然中断前未落盘的用量。

曾尝试的输入精简、大批次方案没有稳定保持质量，已撤回；当前保留原请求、分类 16／审核 8、
阶段统计和任务内持久化检查点。实验名中的 `final` 不代表采用版本，取舍与实测见
[token 实验记录](knowledge-graph-history.md#video-graph-token-optimization-2026-11-06)。
