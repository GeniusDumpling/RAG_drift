# 关联密集区域优先展示（2026-10-26）

后续的 v11 新增 [2D / 3D 图谱工作台](graph-ui-3d-2026-10-26.md)，两种维度继续执行本文的选取规则。当前镜像与回退说明请查看该部署记录。

图谱工作台默认隐藏少于 5 个节点的独立子图，优先展示连接较多、彼此关联紧密的区域。孤立节点、两节点单条连线，以及三、四节点的独立小图不占用默认画布名额。仍使用白色力导向画布、统一左侧导航、拖拽、悬停高亮、搜索、数据面板和字幕证据。

## 选取规则

1. 在有效构图版本中，先应用关键词、实体类型、陈述状态、视频范围和邻居跳数等已有查询条件。
2. 按无向连通性识别独立子图，去掉节点数少于 5 的部分。关系展示时仍保留原方向；平行关系、反向关系和自环不重复计算邻居数。
3. 用 k-core 核心层级、核心区域规模和邻居数量优先选择关联丰富的子图，从连接紧密的核心开始，优先加入与已选节点连接更多的邻居。
4. 在节点和关系预算内先保留连通骨架，再补充选中节点之间的其他关系。剩余额度不足以容纳至少 5 个节点及其连通骨架时不加入新的独立子图，避免截断再次产生碎片。
5. 展开邻居时保留当前画布，新增节点随完整连线一起加入，先为新邻居保留连线名额，再补充已有节点间关系，防止连线数量达到上限后留下新孤立节点。

过滤的是独立小图，不会仅因某个节点度数为 1 就删除它：只要连在保留的大图上，叶子节点仍可展示。筛选与搜索后不足 5 个节点的独立子图同样隐藏，此时页面说明没有符合展示条件的图谱，可调整条件或返回全局概览。

默认预算保持不变：桌面 300 节点／500 关系，手动展开后的画布最多 500 节点／1,000 关系；移动端最多 150 节点／300 关系。数量均为上限，不保证填满。

## 接口与数据保留

`GET /video-graph/graph` 新增 `min_component_size`，默认 5，可设为 0 关闭展示筛选，允许范围 0～50。`full=true` 返回当前查询范围内完整有效图谱，同时关闭展示筛选和数量截断；正式前端固定使用最小规模 5，不请求全量结果。

Neo4j 与旧 PostgreSQL 图谱查询共用同一展示选择函数。内部 `get_graph()` 默认不启用展示筛选，GraphRAG 检索仍能查到小型子图和相关证据。构图任务、实体关系存储、断言及字幕证据不因展示筛选而删除或合并。右侧全局统计继续包含全部有效数据，画布与底栏只计当前展示结果。
