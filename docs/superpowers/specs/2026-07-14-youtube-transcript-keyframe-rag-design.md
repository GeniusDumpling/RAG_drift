# YouTube 字幕与关键帧 RAG 摄取设计

## 1. 目标

将现有“下载完整视频并把公网媒体 URL 交给 VLM”的视频分析方式，替换为只处理公开
YouTube 视频的轻量摄取链路：优先获取公开字幕，没有字幕时使用本地 Whisper 转写，
再结合标题、简介和自适应关键帧生成结构化中文摘要并写入现有 RAG。

设计必须同时满足：

- 不长期保存完整视频、音频或关键帧图片；
- 不要求公网 IP、文件服务器或临时公网媒体 URL；
- VLM 不直接读取完整视频或音频；
- PostgreSQL 保留可追溯的文本证据和处理诊断；
- Qdrant 只保存可从 PostgreSQL 重建的 Chunk 向量；
- 任何成功、失败、超时和取消路径都清理临时媒体文件。

## 2. 范围

第一版只接受公开、无需登录的 YouTube 视频 URL。输入可以来自现有视频发现流程或用户
直接提供的 URL，但搜索、定时调度、Bilibili 和其他视频平台不属于本设计范围。

第一版不绕过登录、验证码、地区限制、付费墙或平台反爬措施，不使用浏览器 Cookie，
不保存完整视频，不建设对象存储和公网文件服务。

## 3. 方案选择

采用“分阶段证据融合”：

1. 获取稳定页面 URL、video ID、标题、简介、频道和时长；
2. 优先获取公开字幕，必要时用本地 Whisper 转写临时音频；
3. 从低清晰度远端视频流中自适应截取临时关键帧；
4. 长字幕先分段提取带时间戳的事实；
5. 最终多模态模型接收标题、简介、字幕事实和内联关键帧；
6. 结构化摘要、字幕、证据时间点和处理元数据写入 PostgreSQL；
7. 摘要与字幕分块后写入 Qdrant；
8. 统一清理临时音频和关键帧。

不采用单次提交完整字幕和所有图片的方式，因为长视频容易超过上下文或请求体限制；
也不采用完全分离的文本摘要与逐帧描述方式，因为调用次数较多，而且最终模型看不到
原始图片。

## 4. 架构与组件边界

### 4.1 YouTube 元数据适配器

使用 `yt-dlp` 读取公开视频元数据和可用字幕信息。适配器负责 URL 规范化、video ID
提取、allowlist 校验和格式选择。稳定入库 URL 固定为：

```text
https://www.youtube.com/watch?v=<video_id>
```

临时签名媒体 URL 只存在于当前进程内存和受控子进程参数中，不进入日志、数据库或
最终命令输出。

### 4.2 字幕与转写组件

字幕来源按以下顺序选择：

1. 视频发布者提供的公开人工字幕；
2. YouTube 公开自动字幕；
3. 临时提取单声道低码率音频并调用本地 Whisper。

字幕必须规范化为带起止时间的段落。只有前两类字幕都不可用时才能启动音频提取和
Whisper。Whisper 失败或输出为空时，该视频处理失败，不能用标题和简介冒充完整摘要。

### 4.3 自适应关键帧组件

FFmpeg 从低清晰度视频流读取画面并输出临时 JPEG，不保存完整视频文件。帧数上限由
视频时长决定：

| 视频时长 | 帧数上限 |
|---|---:|
| 不超过 5 分钟 | 6 |
| 5–15 分钟 | 10 |
| 15–30 分钟 | 16 |
| 30–60 分钟 | 24 |
| 超过 60 分钟 | 32 |

选帧步骤：

1. 通过场景变化检测生成候选帧；
2. 将时间轴分区，保证候选覆盖整个视频；
3. 优先保留场景变化分数较高的帧；
4. 排除黑屏、片头重复和静态重复画面；
5. 使用感知哈希去重；
6. 候选不足时使用均匀时间点补齐；
7. 缩放并压缩成受控大小的 JPEG；
8. 在总图片字节预算内按质量排序发送。

关键帧通过多模态 API 支持的内联 Data URL 或文件上传能力发送，不生成公网图片 URL。
如果总负载超限，先降低图片尺寸和 JPEG 质量，再减少低优先级帧。

### 4.4 字幕压缩与摘要组件

短字幕直接进入最终摘要调用。长字幕按时间窗口切分，每段先提取带起止时间的事实，
再将这些事实、标题、简介和原始关键帧交给最终多模态模型。

最终模型返回结构化 JSON，至少包含：

- 视频概述；
- 涉及的无人机型号与参数；
- 操作、实验或演示过程；
- 故障、安全或脆弱性信息；
- 关键结论；
- 带时间戳的字幕证据；
- 带时间点的视觉证据；
- 不确定信息及字幕与画面的冲突。

视觉事实必须关联至少一个关键帧时间点，字幕事实必须关联字幕时间范围。字幕与画面
冲突时保留冲突说明，不自动选择其中一方为真。

### 4.5 RAG 持久化组件

PostgreSQL 仍是事实来源。Qdrant 只保存 Chunk 向量和引用 PostgreSQL 身份的 payload。
视频处理成功后使用现有切块与索引服务，避免建立第二套向量写入逻辑。

## 5. 端到端数据流

1. 校验 URL、依赖、配置、临时目录和数据库连接；
2. 规范化 YouTube URL，通过 video ID 检查已有成功内容；
3. 创建或复用 Source、Job，并创建可观察的 Run；
4. 先创建并提交 `parse_status=pending` 的 RawPage；
5. 获取标题、简介、频道、时长和字幕清单；
6. 按优先级获取字幕；无字幕时提取临时音频并运行 Whisper；
7. 从低清晰度视频流生成、筛选并压缩临时关键帧；
8. 必要时分段压缩长字幕；
9. 调用多模态模型生成结构化中文摘要；
10. 校验输出 schema、非空摘要和证据时间点；
11. 更新 RawPage，创建 ContentItem 和 ContentChunk；
12. 提交 PostgreSQL 后写入 Qdrant；
13. 更新 Run counters、事件、状态和脱敏诊断；
14. 在 `finally` 中清理当前视频的所有临时文件。

## 6. 数据映射

### 6.1 RawPage

`RawPage` 保存：

- 稳定 YouTube URL；
- 标题、简介、频道、时长和公开发布时间；
- 完整带时间戳字幕或 Whisper 转写；
- 字幕来源：`manual_caption`、`automatic_caption` 或 `whisper`；
- 关键帧时间点、感知哈希、选取原因和图片尺寸；
- 摘要模型、输入模式、字幕压缩诊断和失败降级信息；
- 脱敏后的结构化摘要原始响应。

RawPage 不保存图片二进制、临时文件路径、签名 URL、Cookie 或密钥。

### 6.2 ContentItem

```text
item_type       = video_description
canonical_url   = https://www.youtube.com/watch?v=<video_id>
source_url      = canonical_url
title           = YouTube 标题
raw_text        = 完整字幕或 Whisper 转写
summary_text    = 结构化中文摘要的用户可读版本
cleaned_text    = 结构化摘要 + 可检索字幕正文
language        = zh
structured_by   = youtube-transcript-keyframes-v1
```

`metadata_json` 至少保存 video ID、频道、时长、字幕来源、关键帧请求数和实际数、摘要
输入模式、模型名、降级状态及关键帧时间点。关键帧图片不会长期保存。

### 6.3 ContentChunk

- `summary`：标题、概述、核心结论和结构化领域信息；
- `transcript`：按时间范围切分的字幕，元数据保存起止秒数；
- `visual_evidence`：模型从关键帧确认的画面事实，元数据保存对应时间点。

Qdrant payload 保存 content item ID、video ID、稳定 URL、Chunk 类型和时间范围。检索
结果始终返回稳定 YouTube 页面 URL。

## 7. 失败与降级

| 失败阶段 | 行为 |
|---|---|
| 元数据获取失败 | 视频失败，不创建 ContentItem |
| 人工字幕不存在 | 尝试自动字幕 |
| 所有公开字幕不存在 | 提取临时音频并运行 Whisper |
| Whisper 失败或为空 | 视频失败，不生成标题简介式伪摘要 |
| 场景检测失败 | 降级为均匀时间点抽帧 |
| 部分关键帧失败 | 使用成功帧继续并记录 warning |
| 所有关键帧失败 | 使用 `transcript_only` 生成摘要并记录降级 |
| 图片负载超限 | 压缩后重试一次，再减少帧数 |
| 模型拒绝图片 | 降级为纯文本摘要并标记未使用视觉证据 |
| VLM 超时或无效输出 | 有限重试，仍失败则不创建 ContentItem |
| PostgreSQL 失败 | 回滚该视频的规范化数据 |
| Qdrant 失败 | 保留 PostgreSQL，Chunk 标记 `failed`，Run 为 `partial` |

降级后的摘要必须在元数据和 Run Event 中准确记录输入模式。保存了关键帧元数据不等于
模型成功看过图片。

## 8. 临时资源和安全边界

每个任务使用独立临时目录：

```text
/tmp/intelligence-rag/youtube/<run-id>/<video-id>/
```

第一版采用以下硬边界：

- 默认拒绝超过 120 分钟的视频；
- 单视频临时空间上限 256 MB；
- 关键帧上限 32；
- 不生成完整视频文件；
- 音频使用单声道低码率格式；
- 每张关键帧限制分辨率和字节数；
- 子进程都有 wall-clock timeout；
- 正常、异常、超时和取消路径统一清理；
- 启动时清理超过配置 TTL 的孤立任务目录。

日志、Run 配置、RawPage 和异常信息都不得包含 API Key、Cookie、鉴权头、浏览器
Profile、完整签名媒体 URL或本地临时绝对路径。

## 9. 可观测性

Run counters 延续现有含义：

- `discovered_count`：通过校验的唯一视频数；
- `fetched_count`：成功获取元数据并开始处理的视频数；
- `parsed_count`：获得有效字幕或转写的视频数；
- `extracted_count`：获得有效结构化摘要的视频数；
- `deduped_count`：因 video ID 已成功入库而跳过的视频数；
- `chunked_count`：新建 Chunk 数；
- `embedded_count`：成功写入向量的 Chunk 数；
- `error_count`：视频级和索引级错误数。

事件至少记录字幕来源选择、Whisper 降级、关键帧候选数/实际数、图片负载降级、摘要
输入模式、数据库提交、Qdrant 失败和资源清理结果。

## 10. 测试策略

### 10.1 单元测试

- YouTube URL 规范化、allowlist 和 video ID 去重；
- 字幕来源优先级；
- 只有字幕缺失时才调用 Whisper；
- 五档时长对应的关键帧上限；
- 场景候选排序、时间轴覆盖、黑屏与重复帧过滤；
- 图片总负载预算和降级顺序；
- 字幕分段及时间范围；
- VLM JSON schema 和证据时间点校验；
- 各阶段状态与 Run counters；
- 凭据、签名 URL 和路径脱敏。

### 10.2 集成测试

使用假的 `yt-dlp`、FFmpeg、Whisper 和 VLM 覆盖：

- 人工字幕路径；
- 自动字幕路径；
- Whisper 降级路径；
- 关键帧部分失败和全部失败；
- 图片负载超限重试；
- VLM 纯文本降级；
- PostgreSQL 成功而 Qdrant 失败；
- 任意异常后临时目录为空；
- 相同 video ID 再次导入时不重复处理。

### 10.3 Live smoke

只处理一个公开短视频，人工确认：

- 没有生成完整视频文件；
- 没有启动公网文件服务；
- 摘要同时反映标题、简介、语音内容和画面信息；
- RawPage、ContentItem、Chunk 和 Run 血缘完整；
- Qdrant 可用时，中文查询能命中摘要或字幕；
- Evidence 返回稳定 YouTube 页面 URL；
- 任务结束后临时目录为空。

## 11. 验收标准

1. 公开字幕存在时不提取音频、不调用 Whisper；
2. 无公开字幕时能够用本地 Whisper 生成带时间戳转写；
3. 关键帧数量符合时长档位、场景覆盖和 32 帧硬上限；
4. 最终摘要使用标题、简介、字幕或转写以及可用关键帧；
5. 不需要公网 IP、文件服务器或公网媒体 URL；
6. 不长期保存完整视频、音频或关键帧图片；
7. 每个成功视频至少生成一个 summary Chunk；有有效字幕时还生成 transcript Chunk；
8. 有视觉证据时生成可关联关键帧时间点的 visual_evidence Chunk；
9. Qdrant 失败不丢失 PostgreSQL 事实数据；
10. 所有失败和取消路径都清理临时资源；
11. 日志和数据库不存在密钥、Cookie、签名 URL 或临时绝对路径；
12. 重复导入同一成功 video ID 时跳过重复媒体处理。

## 12. 第一版非目标

- Bilibili、Vimeo 或其他视频平台；
- 视频搜索、定时调度或前端任务管理；
- 登录态、Cookie 和受限内容；
- 完整视频或音频长期保存；
- 关键帧图片长期保存或对象存储；
- 说话人分离和身份识别；
- 多视频并行处理；
- 新建通用媒体资产表；
- 将视频媒体直接交给远端 VLM。
