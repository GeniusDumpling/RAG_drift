# 三维联动性能对比与回退

三维弹性联动上线后出现卡顿。检查发现每次模拟 tick 都将全部节点的位置提交给 G6，鼠标松开后仍持续执行模拟和绘制。

尝试过局部优化：只模拟拖动节点、最近 12 个邻居及最多约 36 个固定边界锚点；只提交位移超过阈值的节点，缩短收敛过程。未将实验版部署到正式服务。

在同一浏览器、同一份 300 节点／337 关系图谱中，拖动同一个 37 度节点、执行相同的 45 步鼠标移动并观察松开后 600 ms：

| 指标 | 原版 | 全图联动 | 局部联动实验 |
| --- | ---: | ---: | ---: |
| 单次最大提交节点数 | 1 | 300 | 13 |
| 累计提交节点数 | 45 | 41,700 | 1,785 |
| 脚本耗时 | 646.698 ms | 10,679.017 ms | 1,537.833 ms |
| 整个操作及观察耗时 | 5,667.908 ms | 26,188.701 ms | 11,656.771 ms |

这是使用无头浏览器与软件 WebGL 的一次对比，不能直接推算用户设备帧率。局部实验虽明显降低开销，但脚本耗时仍约为原版 2.4 倍，操作完成也更慢。因此按用户要求回退到弹性联动之前的 `rag-graph-browser-2d:20261111-v2`。

正式应用恢复为原容器 `c47945741aed3fd64eab68b53b0c81360e49f01601e69409bb4f7d1f68139db0`，健康检查通过，`.env` 镜像配置同步恢复。三维只移动被拖动节点；二维名称显隐与零逐帧 React 提交保留。三维源文件同步恢复到联动前实现，联动代码与局部实验归档到数据目录，避免后续构建误发布。

回退后浏览器验证：邻居不再移动，旋转视角后的真实 300 节点拖拽跟随鼠标，二维概览名称数为 0、放大恢复为 637，布局及缩放期间 React 提交为 0，无页面脚本异常。相关 16 项前端测试及生产构建通过。

性能报告和实验源码：`data/browser-checks/graph-3d-drag-performance-20261112/`；回退后的正式服务检查：`data/releases/graph-3d-rollback-20261112/`。
