# 实体与关系抽取流程优化及 golden 集对照

状态：2026-11-05用户选择恢复旧提示词优化版 `c88ca83a8725`。本页为已停止采用的四环节候选实验记录；下文“当前”“最终”及源码核验均指当时运行，不代表现工作区。候选实现及测试已归档，当前入口见[关系评测说明](relation-gold-evaluation.md)。

本轮按四个环节调整字幕切片的主抽取流程：前置事实审核、后置检索价值筛选、结合关系保留实体、一次有界的端点补漏。测试使用用户复核的 entity-gold-v3（101条实体）及 relation-gold-v3（77条关系），20段，中英文各10段。模型及推理参数保持不变。

## 实际执行顺序

```text
原文及消歧上下文
  → 实体候选、原文术语及故障候选
  → 独立事实审核：原文、类型、身份、属性
  → 实体归一化，形成事实候选池
  → 有界实体对分类 → 独立关系审核及来源校验
  → 检查遗漏端点一次（最多8项）
      → 补充项原文定位 → 独立事实审核及归一化
      → 只对涉及新端点的实体对分类、独立审核
  → 结合原文和已审核图做最终价值筛选
  → 同步筛选实体、关系与证据索引，完整校验后返回
```

当时的实现入口为LLMVideoExtractor.extract，新编排文件为`video_graph_pipeline.py`；源码见[四环节候选快照](../data/video_graph_runs/relation-flow-r4-source-20261105.tar.gz)，恢复旧版后已从运行目录移除。摘要保持只抽实体，不进入关系或补漏步骤。本次评测不连接或回填 Neo4j，不修改金标准答案及评分器。

### 四个环节的约束

1. **事实先核验**：实体原文必须能定位；类型、规范身份、所有者和属性仍需证据。数值参数不能以“延后筛选”为由变成实体。属性拒绝不会自动删除有依据的实体。
2. **价值后判断**：初抽和事实审核不再仅因泛称、无型号或价值暂不明确就淘汰部件、配套设备及维修对象。最终价值判断同时读取原文、实体和已审核关系；有独立信息的孤立实体也可以保留。
3. **关系参与最终保留**：有事实关系不等于必须入图。最终裁决只提供保留掩码，不能改写已核验的类型、身份、属性、谓词、方向、断言或条件。删除实体时同步删除关联边；关系证据保持一一对应并重编号。
4. **补漏只执行一轮**：最多8个有原文的新端点，受每段60个实体总容量限制。补充不能覆盖既有key或身份，也不能凭常识创建缺失型号。新实体须独立审核，关系也须独立审核；没有最终保留关系的新端点不会作为孤立节点发布。没有事实锚点的空实体池不执行补漏。

实体对继续受类型、原文位置及96对预算限制；补漏的“涉及新端点”过滤在预算截断之前执行。分类每批16对、事实关系审核每批8条，最终最多80条关系。开箱语境新增显式开箱/打开包装表达，同时保留主体切换及实际安装的区别校验。独立审核未返回条件字段时保留原有合法范围，显式非法范围仍拒绝；类型唯一的反向关系在独立审核前及审核后校正。

## 对照与复现原则

开始本轮时，工作区策略是 `fd75b10b58bd`，与历史提示词优化的 `c88ca83a8725` 不同。本轮重新测量工作区直接基线，不将历史较低分数作为直接对照。基线源码保存在 [源码快照](../data/video_graph_runs/relation-flow-before-source-20261105.tar.gz)。

固定输入为 [关系快照](../data/video_graph_runs/relation-gold-v3-reviewed-20261105.json) 和 [实体快照](../data/video_graph_runs/entity-gold-v3-relation-baseline-20261105.json)。模型只接收标题和正文，答案、models及notes不进入请求。实体和关系指标来自同一次完整抽取输出，避免分别重跑后挑分。

关系主指标为端点身份、类型、方向、谓词及断言一致的微平均F1；严格限定指标还要求qualifiers匹配。金标准实体范围外的边单列待复核，不计关系TP/FP，因此关系Precision不是全图准确率。实体使用现有一对一规范名/提及匹配，不进行LLM自评分或自由翻译补分。

## 成本、验证与剩余问题

直接基线20段为91次阶段请求，平均4.55次；新流程两组为157/158次，平均7.85/7.90次，范围6–13和5–12次。实际阶段量约为基线1.7倍；这不是费用倍数，未统计供应商token账单。通常至少包含实体初抽、事实审核、关系分类、关系审核、补漏检查及最终筛选；有新端点时增加独立审核与分类。

不含格式修正时的保守上限为每字幕片段37次阶段请求：初抽/事实审核2次，首轮分类/关系审核最多6+10次，补漏检查/事实审核最多2次，补充分类/关系审核最多6+10次，最终价值筛选1次。每阶段最多一次格式修正、每请求最多2次传输，HTTP尝试保守上限148次；未包含视频主题判断。上限不等于平均成本。实体脚本dry-run仍保留旧18/72估算，本轮为保持评分器文件一致未修改该估算；调用量应以本页及原始cache_stats为准。

本地相关测试 **318项通过**，覆盖：前置原文与类型检查、泛称配套端点、孤立实体价值判断、单实体补漏、一次/8项限制、补漏key碰撞、预算前过滤新端点、缺原文补充隔离、补充事实及关系独立审核、无关系补充不发布、节点和边同步删除、价值阶段不得改写身份/谓词/断言/条件、凭据索引及完整结果校验、摘要跳过反馈、现有方向/否定/条件/评分器与缓存约束。条件与假设的最终筛选集成测试均验证原有条件和断言完整保留。

完整离线重放A组20段，所有阶段均命中精确缓存，原始output与评分逐项相同。当前运行代码、测试和金标准与[最终源码清单](../data/video_graph_runs/relation-flow-r4-manifest-20261105.json)一致；本轮六个金标准/评分器保护文件与直接基线快照逐字相同。

仍有明显错误：两组packaged_with均漏掉全部3条标准关系；applied_to、installed_on也仍漏抽。EG001仍把视觉避障系统标为component，且全向避障的条件范围仍可能没有在生成阶段提出。前置与末尾校验能保留、拒绝或筛选已有候选，不能保证模型自动发现所有事实。部分背景、泛称和拍摄功能仍与人工保留口径不一致。下一轮应针对这些错误定位候选生成、类型及谓词选择，而不继续一味放宽实体保留。

这20段已用于开发，不是盲测；没有否定关系标准样本。最终每组7条范围外关系仍待人工复核，未声称全图Precision、通过历史69项发布验收或生产图库质量已改善。本轮完成代码与golden集测试，没有部署、迁移或图库回补。
